# rFkUnCK_you

Локальное приложение Kaev для Telegram Desktop и Discord на сетях с блокировками. Первая публичная бета — Telegram на Windows x64. Discord — следующий релиз. Linux и macOS проверяем после Windows. Свой VPN-сервис — отдельный проект.

## Точка старта

Avalonia-прототип на коммите 03fb7f9 — проверенная основа для переноса. [Flowseal TG WS Proxy v1.11.4](https://github.com/Flowseal/tg-ws-proxy/releases/tag/v1.11.4) запущен через оригинальный CLI во встроенном Python. На текущем ПК в AyuGram прошли сообщения и новое медиа с выключенным TLS для CF. Проверены занятый порт, сбой прокси, остановка при закрытии окна и сохранение ключа. Архив проверен на текущем ПК после распаковки. Публичная бета следует после проверки на чистой Windows.

## Стек и границы

- Один Electron-проект. Electron, React, TypeScript и Vite через electron-vite. CSS для вёрстки, pnpm с lock-файлом, electron-builder для упаковки Windows. [Slipgate](https://github.com/tenstepsbeforedecay/Slipgate) — референс для стека и управления компонентами. Интерфейс, код и графика свои.
- `src/main` владеет процессами, настройками, треем и открытием ссылок Telegram. Для миграции перенеси проверенное поведение C#-контроллера в TypeScript. Адаптер TgWsProxy отвечает за CLI, определение готовности и перевод ошибок. Оригинальный CLI и его зависимости поставляются отдельным ресурсом вне ASAR.
- `src/preload` предоставляет узкий типизированный API через contextBridge. Проверяй входящие данные в main. Запускай локальный интерфейс с изоляцией контекста, sandbox и выключенным nodeIntegration.
- `src/renderer` отвечает за интерфейс и отображение состояния. `src/shared` содержит только общие типы и контракты. IPC передаёт действия и данные приложения. Ссылку с ключом открывает main.
- Позднее Discord получает собственный адаптер и жизненный цикл. Права администратора запрашивает только Windows-компонент, которому они нужны. Системные детали остаются в соответствующих модулях.

## Правила архитектуры

- Держи код, который меняется вместе, в одном модуле. Объединяй код там, где повторяется поведение и совпадают причины изменений. Используй возможности Electron и Node.js напрямую, пока они покрывают сценарий.
- У каждого внешнего процесса один владелец. Сериализуй запуск и остановку, освобождай свои процессы при полном выходе, различай штатную остановку и сбой. Отдельно показывай состояние процесса, готовность локального прокси и подтверждённую работу Telegram.
- Храни настройки пользователя отдельно от поставляемых компонентов. Сохраняй порт, выбор CF-маршрута и ключ между запусками. Переиспользуй валидные настройки Avalonia из %LOCALAPPDATA%/rFkUnCK_you/telegram.json. Записывай настройки атомарно, исключай ключи и ссылки с ключами из логов и Git.
- Держи значения по умолчанию в одном месте. Loopback — граница локального прокси, порт задаётся настройкой. Выбор маршрута зависит от явной настройки и проверяемых возможностей компонента. Для CF-прокси и CF-worker по умолчанию включён TLS. Режим без TLS пользователь выбирает вручную.

## Версии и обновления Flowseal

- Один файл метаданных хранит источник, закреплённую версию и контрольную сумму поставляемого компонента. Сборка, отладка и интерфейс получают версию из него. Закрепляй зависимости сборки в файлах версий.
- Бета поставляет TgWsProxy вместе с приложением. Для обновления собери кандидат в отдельную папку и проверь запуск, остановку, ошибку занятого порта, формат ссылки, совместимость настройки CF, сообщения и медиа. Если изменился CLI, адаптируй только модуль TgWsProxy. Сохраняй предыдущую рабочую сборку для отката.
- Обновление компонентов из приложения — следующий этап. Требования к нему: проверка контрольной суммы по доверенным метаданным, установка рядом с текущей версией и возможность вернуться к ней.

## Порядок работ

1. Создать основу Electron и перенести Telegram. В первой сборке один экран с включением и выключением, статусом, версией движка, «Открыть в Telegram» и настройками. Перенести проверенное поведение завершения, повторного старта и диагностики. Проверить рабочий сценарий из распакованного архива.
2. Проверить Windows x64 на чистой системе и выпустить публичную бету. Приложение — GNU GPL v3.0. В архиве сохраняй лицензии сторонних компонентов и соблюдай их условия распространения.
3. Проверить [Windows-комплект Zapret от Flowseal](https://github.com/Flowseal/zapret-discord-youtube) отдельно из консоли. Проверить текст и голос Discord, отказ в правах и остановку своего процесса. После этого добавить Discord в приложение.
4. Проверить Linux и macOS для каждого компонента отдельно. Объявлять поддержку после реального прогона.
